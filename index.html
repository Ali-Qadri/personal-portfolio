From a doc to a deploy

How every product I make gets built, in seven steps that loop.

  1. 01

    Write it down

    The problem, who it is for and what done looks like, before any design.

    Brief ProblemWho it is forRequirementsOut of scope

  2. 02

    Turn it into Markdown

    One .md file holds the goals, rules and decisions. My AI tools read it too.

    # PrepRoom
## Goal
Students focus together
in one shared room.

## Rules
- Check every sensitive
  action on the server
- One typeface, calm motion

  3. 03

    Design the system

    Wireframes and prototypes in Figma, then a small design system to build from.

    Aa Type, colour roles, spacing

  4. 04

    Build in slices

    One feature at a time, from the interface down to the database.

    • Sign in and roles
    • Rooms
    • Shared timer
    • Chat

  5. 05

    Test against the doc

    Every requirement checked by hand, plus speed, accessibility and SEO.

    • Requirements met
    • Works on a phone
    • Lighthouse run
    • No broken links

  6. 06

    Ship it

    Deployed on Vercel, Netlify or Cloudflare, so real people can use it.

    Live Deployed from main

  7. 07

    Improve it, then go again

    Use it, see what breaks, and take what I learn back to step one.

    Back to 01
